# 示例提示词

以下为四个技能的示例调用方式。实际使用时把「项目/PR/改动」替换为你的上下文即可；风格选项为可选项，直接追加在提问中。

## readme-forge（README 生成）

```
为当前项目生成一份 README.md。项目根目录见当前工作区，
请先盘点 package.json 与 src/ 目录再动笔，命令必须真实可执行。
```

```
当前仓库的 README 已经过时，请对照代码重写，篇幅=精简，language=en。
```

## pr-dossier（PR 描述生成）

```
为当前分支的改动生成 PR 描述：先 git diff 与 git log 了解内容，
按变更档案结构输出，标题遵循 Conventional Commits。
```

```
帮我把工作区的未提交改动整理成提交信息草案，篇幅=精简。
```

## changelog-curator（changelog 生成）

```
根据 git 历史更新 CHANGELOG.md，准备发布 1.2.0（上个标签是 1.1.0），
范围=使用者可见，语言=简体中文。
```

```
这个仓库从来没有维护过 changelog，请从最早的提交开始补一份，
粒度=粗。
```

## diff-verdict（代码审查）

```
审查当前分支相对 main 的全部改动，深度=标准，给出结论与问题清单。
```

```
帮我在提交前自查这次改动，只关注=安全 与 正确性，
发现疑似问题请给出验证方法。
```
